# knowledge/ — 蓄積する知見

セッションをまたいで再利用する知見だけを置く。作業ログでも討論用の案でもない。

| 情報の種類 | 置き場所 |
|---|---|
| 一般化できる知見 | `knowledge/<領域>/` |
| 決定と根拠 | `knowledge/decisions/ADR-*.md` |
| 機械が従う仕様 | `../specs/` |
| 測った結果 | `../evaluation/` |
| 完了した作業 | `../CHANGELOG.md` / `../archive/` |

## 知見には必ずステータスを付ける

- `confirmed` … このプロジェクトの実測で確かめた。変更には再測定が要る
- `hypothesis` … 一般論や1件の観察に基づく初期値。実測を添えれば変えてよい
- `case_specific` … 特定のケースにだけ当てはまった。一般化しない
- `deprecated` … 使わない。なぜ捨てたかを残すために置いている

**一般化できる知見・まだ仮説・1件だけの判断が同じ棚に並ぶと、次のセッションで
どれに従うか決まらなくなる。** これが蓄積で一番よくある失敗。

## 次回の品質へ効く経路

```
人の修正・採否 → 誤りの種類を集計 → 仮説を更新 → 固定ケースで再測定
→ 改善した版だけを既定へ昇格 → 次回に適用
```

**再測定まで行かないと、知見ファイルを増やしても品質は上がらない。**
